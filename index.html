연결한 뒤에는
모델을 고른다

연결과 선택은 다른 단계

새 작업의 모델 선택기에서 사용할 모델을 고른다. 기본값은 Settings › Models › Task models에서 정할 수 있다. 연결했다고 모든 작업의 모델이 자동으로 바뀐다고 생각하지 말자. 기본 모델 ↗ 작업 설정 ↗

첫 작업은 작게

공개 문서 한 개를 요약하게 하고, 출처와 빠진 내용을 확인한다. 처음부터 “블로그 사업 전체 맡아”는 범위가 너무 크다.

안 보이는 모델은 확인부터

연결 상태·구독 자격·실제 모델 목록을 확인한다. 원하는 모델을 쓸 수 없으면 임의로 바꿨다고 숨기지 말고 알려달라고 요청하자.

요금도 한 번 들여다보기. Aside 플랜·크레딧은 Settings › Plan & Usage에서 확인한다. 모델·속도에 따라 크레딧 사용량이 달라질 수 있다. 외부 제공자의 한도와 비용은 따로 확인하자. 사용량 확인 ↗

03

에이전트에게
역할을 나눈다

모델 선택 ≠ 자동 인재 배치

모델은 어떤 AI를 쓸지, 위임은 일을 어떻게 나눌지다. 작업 환경에서 쓸 수 있는 하위 에이전트가 있으면 조사·작성·검토처럼 일을 나눌 수 있다. 그렇다고 Aside가 언제나 ‘최적의 모델’을 자동 선정한다는 보장은 없다.

공식 작업 문서는 여러 단계 수행·대기·승인 요청을 설명한다. 아래 위임 사례는 이번 대화의 실제 실행 기록이며, 모든 모델·계정에서의 재현을 보장하는 제품 규격은 아니다. 공식 작업 범위 ↗

실제 테스트 · 확인 범위를 좁게 읽기

요청: 사용자가 Opus로 10초 파일럿을 요청.
결과: 주 작업이 Claude Opus를 지정한 하위 작업에 애니메이션 HTML을 맡기고, 이후 별도 단계에서 무음 영상으로 변환. 외부에 게시하지 않음.

이 사례는 주 작업의 명시적 모델 지정과 위임을 보여주며, 자동 모델 선택 실험은 아니다. 완성 영상 품질, 음성 제작, 자동 발행까지 검증한 것은 아니다.

  • 역할: “조사는 출처 수집, 검토는 오류 지적만.”
  • 결과물: “각자 결과를 구분하고, 마지막에 하나로 정리.”
  • 경계: “쓸 수 없는 에이전트는 알리고, 게시·결제는 하지 마.”
04

블로그라면
이렇게 써보자

제안하는 흐름 · 실행 완료 아님

“수익 나는 글 알아서 올려”보다 궁금증 하나를 근거 있는 초안으로 바꾸는 일부터. 글을 빨리 만드는 것과 돈을 버는 것은 같은 결과가 아니다.

  1. STEP 1조사공식 출처
    사실·추정 분리
  2. STEP 2초안질문 → 원리
    쉽게 풀기
  3. STEP 3검토오류·과장
    경험 날조 확인
  4. STEP 4사람 승인내 경험·관점
    최종 확인
  5. STEP 5발행승인 뒤
    별도 실행

주제 예시: “AI 브라우저에 모델을 연결하면, 로그인 정보도 AI가 보는 걸까?” 공식 설명을 읽고 실제로 확인한 범위만 쓰는 식이다.

위 흐름은 설명용 예시다. Aside에게 블로그 원고뿐 아니라 HTML 설명 페이지를 만들고 미리보기까지 확인해 달라고 요청할 수도 있다. GitHub 공개와 블로그 발행은 사이트 접근 권한, 로그인 상태, 게시 내용과 사용자 승인을 확인한 뒤 별도로 진행한다. 모든 환경에서 자동으로 성공하거나 수익이 생긴다는 뜻은 아니다.

권한은 넓게보다, 필요한 만큼

공식 문서상 새 작업의 기본 권한은 Guard다. 파일 접근 모드와 도구의 Allow / Ask / Deny 규칙을 확인하자. 웹 탐색·실행 권한도 관련되므로 Read only를 웹 행동 전체의 안전장치로 가정하지 않는다. 게시·결제·삭제는 요청문에도 금지하고, 관련 도구 권한도 확인하는 편이 좋다. 권한 규칙 ↗

공식 문서는 비밀번호 자동입력 시 저장된 비밀번호 값이 에이전트에 노출되지 않는다고 설명한다. 그래도 로그인된 페이지의 개인정보나 실행 가능한 행동은 별개다. 처음에는 공개 자료와 좁은 작업 폴더를 쓰고, 민감정보가 있는 화면은 필요한 범위만 허용하자. 자동입력 보호 ↗

연결은 시작 버튼. 최종 판단까지 넘기는 버튼은 아니다.

AI 연결 문서 ↗작업 문서 ↗보안·권한 문서 ↗구독·사용량 문서 ↗

2026.11.06 공식 문서 확인 기준. UI·제공 모델·구독 조건은 변경될 수 있습니다. 제품 가격은 싣지 않았습니다. 공식 설명, 사용자 제공 테스트 사례, 제안 흐름을 구분했으며 모든 UI나 경쟁 제품 기능을 직접 시험한 것은 아닙니다.
